# Calm v1.4 Reading-Craft Polish

## Status

All four checkpoints were implemented, accepted, and synchronized for the
v1.4.0 release from commit `7659112`.

This specification narrows Calm v1.4 to four independently reversible polish
checkpoints. Each checkpoint was committed, rebuilt, validated, and reviewed
before release synchronization.

## Product Direction

Calm should become more precise without becoming more conspicuous.

The release preserves:

- the existing `41.5625rem` article measure;
- the current light and dark palettes;
- the serif reading surface and body-heading scale;
- media and caption treatment;
- Tap + Scrub mechanics, keyboard focus, and reduced-motion behavior;
- the hybrid heading/depth rail logic;
- complete rail removal on compact phone, Split View, and short coarse-pointer
  landscape layouts.

The release does not add an appearance picker, iconography, cards, a persistent
rail label, a progress bar, or any new NetNewsWire controls.

## Feature Checkpoints

### 1. Responsive title hierarchy

At layouts wider than `820px`:

- set the article title to `1.8 ×` the reader base size;
- use a `1.16` line height;
- use `-0.025em` letter spacing;
- increase article-header-to-body separation to `2.5rem`.

At compact layouts matching the existing query:

```css
(max-width: 820px), (pointer: coarse) and (max-height: 500px)
```

- retain the title at `1.6 ×` the reader base size;
- retain its `1.2` line height and `-0.02em` letter spacing;
- retain the existing `2rem` header-to-body separation;
- retain the existing 44-point title-link touch target.

Article-body heading sizes, article measure, palette, and media treatment remain
unchanged.

Review short and long titles at:

- Mac desktop, `1440 × 1100`;
- iPad portrait, `834 × 1194`;
- iPad landscape, `1194 × 834`;
- Split View, `744 × 1133`;
- iPhone portrait, `390 × 844`;
- short coarse-pointer landscape, `844 × 390`.

### 2. Rail beside the article

Add a paired half-measure token for the unchanged `41.5625rem` reading measure.
At every non-compact width, position the rail just outside the centered article
column with:

```css
right: calc(50% + var(--reader-half-measure) + 0.75rem);
left: auto;
```

Preserve:

- 44-point coarse-pointer targets on iPad;
- the current smaller precise-pointer geometry on Mac;
- complete rail removal and listener suppression for the compact query;
- the article's centered measure and all Tap + Scrub behavior.

### 3. Source identity, conditional read time, and footer removal

The opening metadata keeps the existing feed name as textual source identity.
No source icon is added.

Add a hidden `#readingTime` span after the feed name in both
`Calm.nnwtheme/template.html` and `preview/index.html`.

Continue estimating at 225 words per minute:

- show `N min` only for estimates of four minutes or longer;
- expose a full accessible label such as
  `Estimated reading time: 6 minutes`;
- hide the value when the article is shorter, empty, or cannot be counted;
- prevent doubled or orphaned separators when author, date, feed, or read time
  is absent.

Remove:

- visible word count;
- the statistics-footer markup;
- the footer rule;
- obsolete statistics JavaScript and CSS.

Theme and preview scripts must remain exactly synchronized.

### 4. Intent-revealed reading map

Mark the rail as heading-based only when it uses real heading targets.

On wide precise-pointer layouts at `1080px` and above:

- reveal the active section name to the left of the rail during rail hover,
  keyboard focus, or active scrubbing;
- render it as plain, truncated text;
- use no background, bracket, tooltip arrow, border, or shadow;
- dismiss it with a restrained `120ms` opacity transition.

Do not show section text:

- for depth markers;
- below `1080px`;
- on coarse-pointer iPad;
- in Split View;
- on phone;
- in short coarse-pointer landscape.

On coarse-pointer iPad, intent remains represented only by the existing active
marker strengthening. Reduced motion disables the label transition.

The `1080px` threshold accommodates the article pane in a normal full-window
NetNewsWire layout while preserving the label as a wide, precise-pointer
enhancement.

## Development Record

Each feature was implemented as a separate, independently reversible commit.
For every checkpoint, source and preview behavior were kept in parity, the
installable zip was rebuilt, focused checks and the full validation suite were
run, and the responsive preview matrix was reviewed.

Future changes should preserve that separation: keep a visual or interaction
change focused, add behavior-based validation, rebuild the package when source
changes, and review the affected device classes before merging.

## Validation

### Per checkpoint

Show the same article and top scroll state at all six required viewports. Check
light and dark appearances where applicable.

Automated coverage must include, as the relevant checkpoint is introduced:

- exact wide and compact title values;
- column-relative rail geometry;
- 44-point iPad targets;
- compact rail absence and listener suppression;
- conditional read-time behavior;
- missing-metadata separators;
- footer removal;
- heading-only labels;
- theme/preview script parity;
- keyboard focus;
- reduced motion.

### Release validation

Exercise short, long, structured, depth-marker, missing-metadata, long-title,
image-first, table, code, and embed fixtures at every supported NetNewsWire text
size.

Verify that no checkpoint changes:

- the article measure;
- the light or dark palette;
- media treatment;
- body-heading sizes;
- keyboard focus behavior;
- Tap + Scrub behavior;
- compact rail behavior.
